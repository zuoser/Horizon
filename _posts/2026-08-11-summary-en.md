### [SMM exploit via a very long instruction](https://github.com/xoreaxeaxeax/smiiiiiiiiiiiiiiii) ⭐️ 8.0/10

A security researcher published a GitHub repository demonstrating how System Management Mode \(SMM\) can be exploited using a deliberately very long CPU instruction. The technique targets SMM&\#x27;s assumption that the system is idle between instructions, using instruction timeout behavior to force entry into SMM. The repo has drawn significant Hacker News discussion, and commenters note that firmware designers are already aware of this attack class, with platform implementers expected to choose appropriate timeout values. The work comes from a known low-level security researcher and complements their related Assembly Hall of Shame repo, which catalogs extremely slow single instructions. It is a high-value development in hardware and firmware security because SMM runs below the operating system and is normally invisible to the user.

hackernews · WhiteDawn · Aug 10, 16:03 · [Discussion](https://news.ycombinator.com/item?id=49245491)

**「Background」** System Management Mode \(SMM\) is an extremely privileged x86 processor mode intended for firmware operations like power management and security, entered only via a system management interrupt \(SMI\). Its memory is normally hidden from the operating system, and SMM code runs with higher privilege than the OS, so breaking out of it can give an attacker deep control. This exploit shows that by using an exceptionally long-running instruction, a core can be delayed from acknowledging an SMI, allowing a second core to enter SMM while the first core&\#x27;s long instruction overlaps the SMM handler, potentially hijacking the secure mode.

**「Impact」** The demonstration gives security researchers a concrete way to reach SMM through an instruction-timeout edge case, and it reinforces that firmware designers must carefully choose SMM timeout values to avoid exposing the firmware layer. Since the technique requires root access, its immediate practical threat is limited, but it lowers the barrier for deeper hardware-level control and research.

**「Community discussion」** Commenters confirmed that firmware designers anticipate this attack but delegate timeout selection to the platform implementer, and they appreciated the novel angle of studying the absolute floor of single-instruction performance. Some argued the exploit is not a true vulnerability because it requires root, framing it instead as taking back control of hardware from SMM, while others questioned the practical interactions needed to turn the long instruction into a real attack.

### [Hand-Compiled Transformer Multiplies Exactly, No Training](https://www.reddit.com/r/MachineLearning/comments/1vkrnb5/transformers_are_famously_bad_at_arithmetic_so_i/) ⭐️ 8.0/10

A practitioner hand-set the weights of a stock Phi-3 transformer to perform exact multiplication, achieving 100% accuracy on all 3,000,000 supported three-digit expressions and publishing checkpoints that extend to 12-digit by 12-digit multiplication. The weights were compiled directly from the grade-school multiplication algorithm using Torchwright, a compiler written by the author, without any training. For comparison, six frontier models tested without reasoning scored 0/500 on seven-digit multiplication. The author built four versions — grade-school, hardware-style, scratchpad, and brute-force memorization — that compute the same function while using layers, width, generated tokens, and parameters very differently. This is a proof-of-concept for manually compiling algorithms into transformer weights, relevant to mechanistic interpretability and capability analysis.

reddit · r/MachineLearning · /u/notforrob · Aug 10, 17:37

**「Background」** Transformers are known to be unreliable at exact arithmetic, especially as numbers grow longer, because their learned reasoning often approximates rather than computes. Torchwright is a compiler that translates a computation graph into transformer weights, allowing a standard architecture to implement a known algorithm directly without gradient training.

**「Impact」** This demonstration shows that a stock transformer can encode an exact algorithm through deliberate weight assignment, opening new avenues for interpretability and verification-focused design, though it is not a shift in general-purpose training methods.
