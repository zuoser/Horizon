### [Transformers can do exact arithmetic if you hand-program their weights](https://www.reddit.com/r/MachineLearning/comments/1vkrnb5/transformers_are_famously_bad_at_arithmetic_so_i/) ⭐️ 8.0/10

A developer manually set the weights of a Phi-3 transformer to implement exact multiplication without any training, using Torchwright, a custom compiler that translates a grade-school multiplication algorithm into a standard Hugging Face checkpoint. The resulting three-digit calculator gets all 3,000,000 supported expressions correct, and the published checkpoints support up to 12-digit by 12-digit multiplication. In contrast, six frontier models tested with reasoning disabled showed a sharp accuracy drop as numbers lengthened, with five scoring 0/500 at seven digits. Four versions were built—grade-school, hardware-style, scratchpad, and brute-force memorization—which compute the same function while differing in layer depth, width, generated tokens, and parameter use. This demonstrates that a stock transformer can perform exact arithmetic when its weights are explicitly programmed rather than trained.

reddit · r/MachineLearning · /u/notforrob · Aug 10, 17:37

**「Background」** Transformers are known to perform poorly on exact arithmetic because training typically optimizes for pattern matching rather than algorithmic precision. This work explores an alternative approach: directly programming an algorithm into the network&\#x27;s weights, compiling a computation graph into a standard model checkpoint and bypassing gradient-based training entirely.

**「Impact」** For machine learning practitioners and interpretability researchers, this proof of concept shows that transformer weights can be explicitly compiled to implement exact arithmetic with high accuracy and verifiable behavior, offering a potential path to controllable, exact computational modules. However, the approach requires hand-implementing each algorithm into weights, so it is not yet a general-purpose replacement for training.

### [Rust SIMD on the GPU: Portability and Stability Concerns](https://www.vectorware.com/blog/simd-on-gpu/) ⭐️ 7.0/10

A Vectorware blog post titled &quot;Rust SIMD on the GPU&quot; describes applying Rust&\#x27;s portable SIMD library to GPU programming, an area typically associated with CPUs. The article drew community attention to two limitations: portable SIMD is only available on nightly Rust, and examples that fix SIMD lane widths are not performance-portable across targets. Commenters noted that stable Rust users have turned to the fearless\_simd crate, and some wished for a Rust library with the maturity and scope of Google&\#x27;s Highway C++ SIMD library. The discussion also called for concrete benchmarks of complex GPU algorithms, such as radix sort, to demonstrate competitive performance.

hackernews · sagacity · Aug 10, 18:12 · [Discussion](https://news.ycombinator.com/item?id=49247477)

**「Background」** Rust&\#x27;s portable SIMD library provides a generic SIMD type that maps to CPU vector instructions, but it is only available on nightly Rust, whereas the fearless\_simd crate from the linebender project offers a stable alternative that builds multiple versions of functions per CPU instruction set and dispatches at runtime. On GPUs, a thread is typically a lane within a warp that executes in lockstep with neighboring lanes, making it conceptually closer to a CPU SIMD lane than an independent execution context. Vectorware&\#x27;s blog argues that this lets Rust&\#x27;s portable SIMD treat the GPU as just another vector-hardware target.

**「Community Discussion」** Commenters largely agreed that Rust&\#x27;s portable SIMD remains impractical on stable: one developer switched their FFT crate to fearless\_simd because portable SIMD is nightly-only. Others pushed back on the word &quot;portable,&quot; noting that constant SIMD width makes examples non-performance-portable, and asked for GPU algorithm benchmarks; one commenter also expressed surprise that SIMD applies to GPUs at all.

### [Exploiting SMM with a very long interrupt](https://github.com/xoreaxeaxeax/smiiiiiiiiiiiiiiii) ⭐️ 7.0/10

A security researcher has published a proof-of-concept technique that executes arbitrary code in System Management Mode \(SMM\) by exploiting a very long interrupt on x86 systems. The attack requires root access, so it is not a practical remote threat, but it demonstrates deep hardware control and a novel way to bypass the usual separation between SMM and the operating system. The technique relies on the fact that firmware designers expect the platform vendor to choose an interrupt timeout that is longer than any possible I/O operation, and the readme stresses that the instruction must be extremely long. The project is part of the researcher&\#x27;s broader low-level assembly work and is presented mainly as a hardware-security research demonstration rather than a widespread exploit.

hackernews · WhiteDawn · Aug 10, 16:03 · [Discussion](https://news.ycombinator.com/item?id=49245491)

**「Background」** System Management Mode \(SMM\) is a highly privileged x86 CPU mode used by firmware for low-level tasks such as power management and hardware control; it executes transparently to the operating system and is typically triggered by a system management interrupt \(SMI\). A very long instruction can keep a CPU core occupied long enough that an SMI arrives and is handled while the instruction is still in progress, potentially letting an attacker with root access influence SMM execution and bypass firmware security controls.

**「Impact」** For platform vendors and firmware developers, the technique highlights the need to carefully validate SMM interrupt timeouts, since the firmware explicitly punts this decision to the vendor. Practical end-user risk is limited because the attack requires root access, but it gives security researchers a concrete method for examining and potentially controlling SMM behavior.

**「Community Discussion」** Commenters note that firmware designers already anticipate this attack and delegate the timeout choice to the platform vendor, and one argues that it is not really a vulnerability because root access is required, instead calling it &quot;taking back control of your hardware.&quot; Another commenter questions whether a very long instruction alone is enough, since the attack would need the instruction to interact with whatever SMM is doing at the same time.

### [Intel, Verisk, Berkshire and GameStop Lead Premarket Stock Moves](https://www.cnbc.com/2026/08/10/stocks-making-the-biggest-moves-premarket-aapl-hpe-rklb-and-more.html) ⭐️ 7.0/10

Intel fell 3% premarket after announcing a $15 billion common stock offering; Verisk dropped more than 6.5% after a Delaware judge ordered it to complete its $2.35 billion AccuLynx acquisition. Berkshire Hathaway rose 0.5% after reporting 16% second-quarter operating earnings growth, and GameStop gained 1.5% on a Bloomberg report it may abandon its $56 billion bid for eBay.

rss · CNBC Finance · Aug 10, 13:52

**「Background」** Verisk had terminated the AccuLynx deal in December after a Federal Trade Commission review missed the termination date, and eBay rejected GameStop&\#x27;s unsolicited bid in May as &\#x27;neither credible nor attractive.&\#x27;

**「Impact」** Intel&\#x27;s share offering could dilute current shareholders, while Verisk is now compelled to spend billions on a court-ordered acquisition.
